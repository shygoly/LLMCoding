# Sales Demo Script For Healthcare AI Assistant

## 目标
提供一套可直接用于客户演示的销售脚本，使“健数通 / 健康管理 AI 助手”既能被客户快速理解，又能自然带出背后的平台能力与后续合作空间。

## 适用场景
- 企业客户初次演示
- 架构咨询前的产品展示
- PoC 销售场景
- 健康管理 / 护理运营 / 医疗辅助场景的 AI 项目演示

## 前提条件
- 已准备好演示环境
- 至少有一个租户、一个管理员、一个普通用户账号
- 已准备机构文档、示例记录和基础 usage / audit 数据
- 演示范围聚焦低风险辅助场景，不演示高风险自动诊疗闭环

## 输入
- `reference-enterprise-ai-demo-project.md`
- `transform-homecare-admin-into-ai-saas.md`
- `demo-project-roadmap-for-healthcare-ai-assistant.md`

## 核心步骤
1. 先讲业务价值，不先讲平台概念
2. 用一条完整业务链路证明“这不是聊天玩具”
3. 再展示多租户、审计、usage 等平台能力
4. 最后讲扩展路径与合作方式

## 演示总时长
建议控制在 12～18 分钟。

推荐节奏：
- 2 分钟：业务问题
- 6～8 分钟：核心产品演示
- 3～4 分钟：平台能力演示
- 2～3 分钟：合作与下一步

## 演示结构

### 1. 开场：先讲业务问题
建议话术：
- 健康管理和护理运营场景里，机构通常面临文档分散、知识查找慢、记录整理耗时、流程执行不一致的问题。
- 这个示范项目不是单纯的聊天机器人，而是把机构知识、记录处理和平台治理能力整合到一个企业级 AI 助手中。

目标：
- 让客户先理解业务价值
- 不要一上来就讲架构术语

### 2. 第一段演示：机构知识问答
演示动作：
- 进入某个租户 / 机构后台
- 展示已上传的制度、护理规范或服务文档
- 从用户侧提出一个真实业务问题
- 展示系统回答并引用来源

要强调：
- 这是机构自己的知识，不是通用问答
- 回答有引用，可追溯
- 可以减少培训和查资料时间

### 3. 第二段演示：记录总结 / 报告草稿
演示动作：
- 打开一段较长的服务记录或护理记录
- 一键生成结构化摘要或报告草稿
- 展示总结结果如何帮助后续记录与汇报

要强调：
- AI 在做辅助整理，不是替代专业判断
- 重点是提高文档处理效率

### 4. 第三段演示：多租户与权限
演示动作：
- 切换到另一个租户或账号
- 展示该账号无法访问前一个机构的知识和记录
- 展示管理员与普通用户看到的能力差异

要强调：
- 这不是单机 demo，而是企业 SaaS 能力
- 知识库、权限和上下文是租户隔离的

### 5. 第四段演示：审计与 usage
演示动作：
- 打开 audit 面板
- 展示谁提了什么问题、何时生成了什么结果
- 打开 usage / quota 面板
- 展示租户的使用趋势或基础统计

要强调：
- 企业真正需要的不只是“AI 能回答”，还需要“可管理、可审计、可控成本”

### 6. 第五段演示：workflow / 后续扩展
演示动作：
- 展示一个简单 workflow 状态页，或说明多步骤能力（如记录总结 -> 报告草稿 -> 管理员确认）
- 强调该项目可继续扩展成更完整平台

要强调：
- 当前是最小可用形态
- 但已经具备继续演化为企业 AI 平台的骨架

## 演示中的禁区
为了避免客户误解，建议不要在第一版演示中：
- 承诺自动医疗诊断
- 演示高风险处方或用药决策闭环
- 把 AI 输出包装成“专业结论”

建议统一表述为：
- 知识辅助
- 记录辅助
- 报告辅助
- 运营辅助

## 平台能力如何自然带出
不要先讲：
- Policy Engine
- Workflow Engine
- Billing
- Skill Graph

建议在演示后自然补充：
- 不同角色看到的能力不同，这是权限策略层
- 不同机构互相隔离，这是多租户能力
- 所有操作可追踪，这是审计能力
- 可统计使用量，这是 usage / billing 能力
- 可扩展多步骤任务，这是 workflow 能力

## 常见客户提问与回答方向

### Q1：这和普通知识库问答有什么不同？
建议回答：
- 它不是孤立问答工具，而是嵌进业务系统的企业 AI 助手，具备权限、租户、审计和后续流程能力。

### Q2：如果我们有多个机构 / 部门怎么办？
建议回答：
- 系统支持租户边界和角色边界，不同机构的数据、知识和 usage 可以隔离管理。

### Q3：能不能接我们的业务流程？
建议回答：
- 当前示范项目已经预留了 workflow 能力，后续可以把 AI 从问答扩展到记录、报告、审批和运营场景。

### Q4：如果输出错了怎么办？
建议回答：
- 第一阶段定位为辅助，不直接替代专业判断；同时系统提供引用来源、审计记录和后续可加入人工确认环节。

## 演示结束的收口方式
建议结尾话术：
- 这个示范项目展示的不是单点 AI 功能，而是一套可以逐步落地到企业场景的 AI 应用骨架。
- 我们可以先从知识助手和记录辅助开始，在 4～8 周内做出适合贵方场景的 PoC，然后再逐步扩展成更完整的平台能力。

## 推荐后续动作
演示后建议立刻推进以下动作之一：
- 2 周架构诊断
- 4～8 周 PoC
- 需求工作坊 + 路线图设计

## 验证方式
一个好的演示脚本应满足：
- 客户在 15 分钟内理解业务价值
- 客户能感知“这不是普通聊天机器人”
- 客户能听懂平台能力，但不会被架构术语压垮
- 演示结束后能自然进入下一步商务动作
