# Project Knowledge Graph

## 目标
为 AI Agent 建立持续理解项目的结构化知识层，让 Agent 先理解系统再生成代码，而不是每次冷启动重读代码文本。

## 适用场景
- 多模块、多技术栈的项目
- 需要让 AI 长期维护代码库
- 希望支持跨文件、跨模块、跨架构层级查询

## 前提条件
- 能从代码中抽取文件关系与符号关系
- 有地方记录架构与决策文档
- 至少具备简单的图数据或索引存储能力

## 输入
- 代码库
- 架构文档
- 决策记录
- 数据库与 API 信息

## 核心步骤
1. 构建文件与符号层索引，提取导入、调用、返回、依赖关系
2. 把模块、服务、数据库、外部 API 抽象为更高层节点
3. 把架构文档和决策文档导入统一图谱，建立描述关系
4. 为 Agent 提供查询入口，要求先查询再实施代码修改
5. 周期性更新图谱，避免文档层与代码层漂移

## 产物
- 文件图、符号图、模块图、架构图、决策图
- 可查询的统一项目知识图
- 面向 Agent 的检索接口或提示策略

## 风险与边界
- 如果只做符号索引而没有架构与决策层，长任务仍容易偏航
- 如果只写文档而不和代码同步，知识库会快速失真
- 小项目未必需要完整六层 PKG，可从符号图与决策图起步

## 验证方式
- Agent 能回答“已有逻辑在哪”“谁依赖谁”“为什么这么设计”
- 新功能实现中，重复造轮子现象减少
- 架构变更后，可较快同步图谱与文档
