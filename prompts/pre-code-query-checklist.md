# Pre Code Query Checklist

请在开始写代码之前，先完成一次“项目知识查询检查”，不要直接实现。

## 目标
确认本次任务的：
- 所属模块
- 已有实现
- 依赖关系
- 架构边界
- 历史决策
- 最小改动落点

## 使用方式
把下面检查单作为编码前的固定步骤。若信息不足，先补检索结论，再开始改代码。

## 检查单

### 1. 任务定位
回答：
- 这个任务属于哪个模块、页面、服务或能力域？
- 它更像新增功能、修复问题、重构，还是知识整理？

### 2. 已有实现检索
回答：
- 项目里是否已有相似功能、相似页面、相似 API、相似组件？
- 最接近的现有实现在哪些文件？

### 3. 依赖关系检索
回答：
- 谁调用当前目标？
- 当前目标会调用谁？
- 依赖哪些数据表、服务、状态、配置或文档？

### 4. 架构边界检索
回答：
- 这一层允许直接访问哪些层？
- 是否存在明确的 API 边界、服务边界、Schema 边界或模块边界？

### 5. 历史决策检索
回答：
- 是否已有相关 `decision`、`principle`、`pattern`？
- 是否存在明确不建议采用的方案？

### 6. 最小修改面确认
回答：
- 本次改动最小应该落在哪些文件或模块？
- 哪些改动是不必要扩散？

### 7. 风险预判
回答：
- 这次修改最可能破坏什么？
- 有没有需要同步更新的文档、Schema、Mock、配置或测试？

## 输出格式
请严格按以下格式输出：

```text
任务定位:
- 

已有实现:
- 

依赖关系:
- 

架构边界:
- 

历史决策:
- 

最小修改面:
- 

风险预判:
- 
```

## 执行要求
- 没有完成以上检查前，不要直接开始写代码
- 如果项目知识不足，先说明缺口，不要假设
- 如果发现现有知识与代码冲突，先记录冲突点
- 如果任务很小，也至少完成“已有实现 / 架构边界 / 最小修改面”三项
